# 7.15.0 dependency review map

The firmware repository records submodules as commit pointers, so GitHub's
parent-repository diff cannot show the code inside a dependency range. Reviewers
must audit the ranges below in the dependency repositories as part of the 7.15
release review.

| Dependency | Old pointer | Release pointer | Range size | Review anchor | Stack placement |
| --- | --- | --- | ---: | --- | --- |
| `deps/crypto/trezor-firmware` | `03d8a55a832fb61bb89477ef7239a80ecb367080` | `cdc05bebe9e6989cf711e1b5bea6324fd09f848e` | 23 commits; 57 files; +6,329/-384 | [keepkey/trezor-firmware#8](https://github.com/keepkey/trezor-firmware/pull/8) | Foundation; required by the firmware crypto features |
| `deps/device-protocol` | `d637b78291a423fd8119df9935a9365be8a7758e` | `cf308fd5e76f3f2e02ba38347ceccaa382b08505` | 33 commits; 18 files; +1,089/-76 | [keepkey/device-protocol#119](https://github.com/keepkey/device-protocol/pull/119) | Foundation; required to generate the feature message types |
| `deps/python-keepkey` | `fabd6c6189b7f1b3ea7cbd1d372fc13729761178` | `b44f1b367e7b8ce98d88a49b3457443335365d8f` | 128 commits; 56 files; +9,868/-1,028 | [keepkey/python-keepkey#211](https://github.com/keepkey/python-keepkey/pull/211) | Final integration bundle; deliberately deferred so foundation CI does not run future-feature tests |

The crypto and protocol ranges are reviewed as dependency baselines rather than
being presented as CI-only changes. The Python client range is applied only
after all firmware feature bundles are present, making its integration suite a
final-stack gate instead of a false failure on the foundation PR.

To reproduce a range review from an initialized checkout, run the following for
each dependency:

```sh
git -C deps/<dependency> log --oneline <old>..<release>
git -C deps/<dependency> diff --stat <old>..<release>
git -C deps/<dependency> diff <old>..<release>
```
